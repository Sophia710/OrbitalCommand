## 1. 项目背景

### 1.1 业务背景

公司在 ToB/ToG 业务拓展中长期面临三类痛点：

- **信息分散、来源单一**：标讯、客户、竞品、政策、行业动态分散在政府采购网、客户官网、公众号、第三方聚合平台等数十个渠道，靠人工每天轮询，效率低且易遗漏。
- **机会识别靠经验、不可复制**：判断"这条标讯是否值得投、这个客户是否值得跟"高度依赖老员工个人经验，团队扩张后无法规模化。
- **跟踪断点、协同弱**：识别出机会后缺乏统一的"标记—订阅—跟进—归档"机制，情报在个人手里，团队无法复用。

### 1.2 集成定位

`frontend/` 项目已构建"数字员工"产品形态（员工广场 → 我的员工 → 任务发布），覆盖了执行型数字员工的完整链路。本需求文档**不构建独立的"市场雷达"系统**，而是**把"市场商机分析数字员工"作为一颗新的预设员工**接入到现有平台，让用户：

1. 在**员工广场**的专业员工分类中看到"市场商机分析员"；
2. 添加到"我的员工"后，通过现有的"发布任务"按钮进入对话式任务界面；
3. 在对话中获得 4 步任务执行过程 + 3 段结构化情报输出；
4. 通过对话界面侧栏**工具箱**管理个人数据源与消息推送。

### 1.3 与 v1.0 文档的关系

v1.0 文档（原 564 行版本）描述的是市场雷达原型的独立产品形态（含三模块：情报雷达/订阅推送/知识库）。  
v2.0（本版）聚焦"如何集成进现有数字员工平台"，**复用 v1.0 的字段体系、6 类数据源、订阅字段作为底层数据/字段来源参考**，但**不构建独立的"情报雷达/订阅推送/知识库"页面**——这三个能力在 v2.0 中演化为"对话式情报问答 + 工具箱"。

## 2. 设计概览

### 2.1 一句话定义

> **市场商机分析数字员工 = 现有数字员工平台中的一颗专业型员工**，通过对话式交互为用户提供 7×24 主动发现的客户/标讯/伙伴/竞品/政策/行业六大类商机分析，**所有能力统一收敛在对话界面 + 工具箱中**。

### 2.2 设计原则

| 原则 | 落地策略 |
| --- | --- |
| **复用优先** | 复用 `ChatOverlay` 对话组件，不新建独立对话页 |
| **对话即界面** | 情报输出、研判结果、检索列表均通过对话流呈现，**不**渲染独立卡片墙 |
| **工具箱收敛设置** | 数据源/推送设置统一收纳在侧栏工具箱弹窗中 |
| **个人级配置** | 工具箱设置按用户隔离（localStorage），无需管理后台 |
| **样式与系统一致** | 严格沿用现有 Element Plus + 主题色，**不**引入新视觉风格 |
| **图表轻量增强** | 输出支持柱状/饼图/雷达图，组件封装在 markdown 流内 |

### 2.3 与 v1.0 三模块的映射

| v1.0 模块 | v2.0 落地形态 |
| --- | --- |
| 情报雷达 | 对话流：用户输入自然语言 → 4 步执行 → 3 段输出 |
| 订阅推送 | 工具箱 → 消息推送弹窗（订阅字段对齐市场雷达原型） |
| 知识库 | 工具箱不承载（项目已有独立知识库模块）→ 对话中可"绑定知识库" |

### 3.3 工程隔离设计（核心约束）

**核心原则**：本集成方案**仅对"市场商机分析员"生效**，对其他任何数字员工（链路诊断员、全链路编排员、终端管理助理、载荷分析员、报告生成员、数据处理员、自定义员工等）**零影响**。其他员工进入对话后看到的界面、流程、消息渲染**与改造前像素级一致**。

#### 隔离策略总览

| 改造类型 | 文件 | 隔离方式 | 风险 |
| --- | --- | --- | --- |
| **A. 共享数据层扩展** | `chat.js` store | 仅新增字段（不修改现有结构） | 0 |
| **B. 共享组件条件渲染** | `ChatOverlay.vue` | 全部 v-if 受 `isMarketRadar` 控制 | 中 |
| **C. 新增独立组件** | MarketChart / DataSourceDialog / PushDialog / KnowledgeBindDrawer | 仅在 ChatOverlay 中按 v-if 引入，其他员工完全不 import | 0 |
| **D. mock 数据注入** | `mock-data.js` / `mock.js` | 仅追加数据，不修改现有员工 | 0 |
| **E. 消息类型兼容** | MessageRenderer | 新增 type 走 `v-if="msg.type === 'chart'"`，未识别 type 走默认渲染 | 0 |

#### 隔离实现：ChatOverlay 内部 v-if 分支

```vue
<!-- ChatOverlay.vue 伪代码 -->
<template>
  <!-- 侧栏：工具箱按钮（仅市场商机分析员） -->
  <button v-if="isMarketRadar" @click="toggleToolbox">🧰 工具箱</button>

  <!-- 工具箱折叠面板（仅市场商机分析员） -->
  <div v-if="isMarketRadar && toolboxOpen" class="toolbox">
    <button @click="openDataSourceDialog">📡 数据源</button>
    <button @click="openPushDialog">🔔 推送</button>
  </div>

  <!-- 输入框旁：知识库绑定按钮（仅市场商机分析员） -->
  <button v-if="isMarketRadar" @click="openKnowledgeDrawer">📎 绑定知识库</button>

  <!-- 消息渲染（所有员工共用，MessageRenderer 内部按 type 分支） -->
  <MessageRenderer :msg="msg" :emp="employee" />
</template>

<script setup>
const props = defineProps({ employee: Object, open: Boolean })
// 关键隔离点：唯一识别标志
const isMarketRadar = computed(() => props.employee?.id === 'market-radar-001')
</script>
```

#### 隔离实现：MessageRenderer 类型分发

```vue
<!-- MessageRenderer.vue 伪代码 -->
<template>
  <!-- 现有类型：完全保留原渲染逻辑 -->
  <ProcessCard v-else-if="msg.type === 'process_card'" :msg="msg" />
  <StepBlock  v-else-if="msg.type === 'step'" :msg="msg" />
  <Markdown   v-else-if="msg.type === 'markdown'" :msg="msg" />

  <!-- 新增类型：仅市场商机分析员会产出 -->
  <MarketChart v-else-if="msg.type === 'chart'" :msg="msg" v-if="isMarketRadar" />
  <ResultList v-else-if="msg.type === 'result_list'" :msg="msg" v-if="isMarketRadar" />
  <DownloadBar v-else-if="msg.actions" :msg="msg" v-if="isMarketRadar" />

  <!-- 兜底：未识别 type 走默认文本渲染（其他员工不会受影响） -->
  <DefaultBubble v-else :msg="msg" />
</template>
```

**关键点**：
- 即使其他员工的 mock 数据意外产出 `type: 'chart'`（不可能但防呆），`isMarketRadar = false` 也会走 DefaultBubble 兜底
- 现有 4 类消息（process_card / step / markdown / 普通）**完全保持原渲染逻辑**，不修改
- 现有右侧面板（进程/文件 tab）**完全不变**

#### 隔离原则备忘

- **永远不要修改 ChatOverlay 现有 prop 接口**（employee / open）
- **永远不要在 mock.js 中覆盖其他员工的 buildInitialMessages 行为**
- **永远不要给员工添加全局新字段**（如 `enableToolbox: true`）污染其他员工
- **唯一识别标志：`employee.id === 'market-radar-001'`**

**4 步执行标准**：

| 步骤 | 标题 | 说明 | ~耗时 |

## 5. 关键交互流程

### 5.1 任务执行流（4 步标准）

```
抽屉关闭 + 输入框上方显示 "已绑定 N 篇"
   ↓
后续该会话的 markdown 输出在 [n] 标记位置引用
```
